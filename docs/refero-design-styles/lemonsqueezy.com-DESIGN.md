# Lemon Squeezy — easy-peasy color blocks

## Overview

Friendly software marketing with an exuberant purple frame and unusually substantial product imagery. Rounded geometric sans headings, restrained interface typography, candy-colored split panels and crisp white space make complicated products feel approachable. The experience is airy rather than dashboard-dense, mixing polished device renders, enlarged interface compositions and playful studio photography.

### Essentials

- A conversational headline behaves like a big, light piece of lettering: Circularpro book at 80px/1, weight 400, -0.04em tracking, white on #5423e7; the default opening puts four short lines beside an oversized device.
- Purple is the architectural frame, not a small accent: #5423e7 owns the opening and the entire closing stage; most explanatory text sits on white or #f7f7f8, while vivid pink, blue and green are concentrated in full-width media panels.
- Actions feel like small white lozenges: 40px radius, 16px 48px padding for the 57px hero action, a 12px arrow and a 12px label-to-icon gap; the navigation version is 40px high with 8px 20px padding.
- The product is staged as a tangible object: a large black-bezel tablet with a silver rim floats in perspective and extends beyond the right edge; repeat a substantial product object in the purple closing stage. When there is no device-worthy interface, mount one meaningful workflow or output in the same dimensional frame.
- Chapters are color-indexed rather than icon-led: 14px/1.6 Inter 500 uppercase labels with 2px tracking sit above 56px regular headings, and slash-number labels introduce 38.4px feature headings in open three-column grids.
- Big flush halves are the signature media device: two 720px-wide planes at desktop, one saturated and one pastel, hold enlarged product compositions without rounded outer containers. White-space-led sections use 160px vertical padding and a 1152px content width.
- Helpfulness becomes a visual chapter: blush-backed resource rows pair physical book mockups or expressive studio portraits with plain 36px headings and tiny white download pills; the ending returns to a giant purple product stage and a four-column link directory. Adapt the resources to the new product rather than repeating its subject matter.

## Typography

- **Circularpro** — All marketing headings and large numerals. Rounded geometric sans with circular counters and a soft, plainspoken regular cut. If unavailable, use **DM Sans**. Use weight 400 and preserve the tight tracking and headline wraps. Font stack: "Circularpro", "DM Sans", sans-serif.
- **Inter** — Paragraphs, navigation, labels, quotes, captions and actions. Neutral, highly legible grotesk; regular paragraphs and medium emphasis. Font stack: "Inter", sans-serif.

### Containers and grids

- **Reading container**: max width 1152px · side padding 40px. Centered desktop alignment shared by navigation and explanatory sections.
- **Expanded grid**: max width 1233px · 3 columns · gap 0px. Feature and testimonial grids; 40px cell padding aligns text close to the reading container while backgrounds extend farther out.
- **Heading pair**: max width 1152px · 2 columns · gap 192px. Eyebrow spans above the left title; heading width 488px and right paragraph about 472px, visually aligned with the heading.
- **Flush split**: 2 columns · gap 0px. Full-width equal halves; each is 720px at desktop. Text stays inward-facing within a 616px wrapper with a 64px inset and 40px gutter.
- **Footer directory**: max width 1152px · 5 columns · gap 24px. Small symbol column followed by four link columns, each about 211px wide.
- **People grid** (only for company and team pages): max width 1152px · 3 columns · gap 72px. 336px-wide unboxed profile columns.

## Surfaces and depth

### Surfaces

#### Reading canvas · level 0

**Use:** Default marketing content.

**CSS:** `background: #ffffff`

**Observed:** White sections alternate with Section gray, with no enclosing outer card.

**Transfer:** Let spacing define chapters rather than adding containers around every paragraph.

#### Purple frame · level 0

**Use:** Opening and closing conversion environments.

**CSS:** `background: #5423e7; color: #ffffff; overflow: hidden`

**Observed:** The navigation merges into the opening; closing headline, oversized device and directory share one continuous field.

**Transfer:** Keep a single uninterrupted color behind all closing elements.

#### Section gray · level 0

**Use:** Alternating reading bands and proof cells.

**CSS:** `background: #f7f7f8`

**Observed:** Flat, extremely light neutral; no visible shadow or bevel.

**Transfer:** Use to separate a capability family or checkerboard quote grid.

#### Paired media planes · level 0

**Use:** Signature enlarged product compositions.

**CSS:** `display: grid; grid-template-columns: 1fr 1fr; gap: 0px; overflow: hidden; background: #f53d6b`

**Observed:** Pink pairs with soft pink; blue with pale sky; green with soft green. Each half reaches the viewport edge and holds an overscaled UI or device.

**Transfer:** Choose one saturated/pastel pair per capability family; maintain square outer edges.

#### Blush resource band · level 0

**Use:** Helpful material and editorial resources.

**CSS:** `background: #feebfc`

**Observed:** A pale pink chapter carries a heading pair and repeated image-left, copy-right rows.

**Transfer:** Carry the same pale pink behind successive resource rows instead of floating separate cards.

#### Technical black · level 0

**Only for:** technical and advanced-product chapters

**Use:** Contrast chapter for specialist audiences.

**CSS:** `background: #000000; color: #ffffff`

**Observed:** White regular-weight headings, dim body copy and lilac media blocks; advanced sales messaging also uses a black device scene.

**Transfer:** Keep dark treatment chapter-scoped, not the default page theme.

#### Tinted reading split · level 0

**Only for:** detailed product explanations

**Use:** Copy alongside a saturated illustrative half.

**CSS:** `background: #eefbf4`

**Observed:** Mint with green, cream with yellow, ice with blue; copy remains dark and backgrounds are flat.

**Transfer:** Keep the reading half markedly less saturated than its media companion.

## Imagery and graphics

### Floating device stage

**Use:** Signature opening and closing product object.

**Observed:** Large black-bezel tablet with a narrow metallic rim, luminous white UI and faint purple charts. Opening art tilts in perspective, casts a broad soft shadow and runs beyond the right edge. The closing device is almost the full content width, about 1267px by 735px.

**Transfer:** Use the new product's meaningful primary screen. If no screen exists, create a simplified workflow or result board in a dimensional dark frame; keep the screen readable and the backdrop purple.

**Build:** Recommended reconstruction: place a white interface inside a near-black rounded frame with a thin light-gray rim; transform the parent using perspective(1400px), rotateX(12deg), rotateY(-18deg) and rotateZ(-8deg). Start around 900px wide in the right half and clip at the viewport edge. Add a separate flattened ellipse below with rgba(18,18,23,0.3), blur 32px. Tune the angle to new content; leave text on a higher layer.

### Overscaled interface diptych

**Use:** Signature full-width capability media.

**Observed:** Checkout windows, marketing forms and black-framed tablets are enlarged on flush saturated/pastel halves. UI frames are white with delicate browser chrome and realistic soft shadows; content sometimes runs past the panel boundary.

**Transfer:** Show one or two useful product outputs per plane, not an entire tiny dashboard collage. Preserve the scale contrast between ordinary paragraphs and monumental product UI.

**Build:** Recommended reconstruction: equal-width overflow-hidden planes; place a white browser window at about 100px inset with an 8px corner radius, tiny colored window dots and a light chrome strip. Add rgba(18,18,23,0.16) soft downward shadow; scale a second UI frame to overlap or extend outside its half. Use pink/soft pink, sky/pale sky or green/soft green consistently.

### Physical resources and studio people

**Use:** Helpful-resource chapter.

**Observed:** Printed guides appear as thick glossy books photographed diagonally on neutral light-gray surfaces, with saturated purple covers and playful cutout people and geometric shapes. **Transfer:** Turn the new product's educational asset into a convincing book, workbook or physical tool. Pair people with warm solid-color studio backgrounds and visible human gestures; avoid generic office stock scenes.

### Explanatory network art

**Only for:** detailed product explanations

**Use:** Make invisible product operations tangible.

**Observed:** White notification plaques float above vivid flat backgrounds, with avatars, country flags and green amounts. A green patterned globe on mint has dashed orbital lines; other diagrams arrange small flags and notifications around dotted circular paths.

**Transfer:** Replace currencies and geography with the new product's entities. Keep one dominant object and a few crisp white annotations.

## Section recipes

How recurring sections are built.

### First screen: Purple product opening

**Observed:** A 70px yellow Announcement band sits above the 88px Navigation. Behind everything is Purple frame. A centered 1152px container divides into equal columns with an 80px gap; text starts about 104px below the navigation. The white 80px/1 Display headline occupies about 536px and four lines on the left, followed after 32px by dim-white Body support and after 40px by Primary button. Floating device stage occupies the right half, deliberately much wider than its column and clipped by the viewport. In the first 900px the announcement, navigation, entire headline, two-line support, action and most of the tablet are visible. The trusted-company strip starts below this opening, its content below the fold.

**Transfer:** Give a different product one clear promise in a similarly narrow headline column and a single tangible output at right. Without original product media, construct a real simplified workflow inside Floating device stage. Pricing and company-story openings use centered text instead, at the same Display scale, with about 144px top and 112px bottom space. A developer-library page adds a 90px secondary product navigation and puts a UI specimen gallery below its centered opening.

**Avoid:** Do not center the default hero, shrink the tablet to fit a small card, add a gradient headline, or crowd the headline with multiple competing calls to action.

**Transfer:** Close with a forward-looking outcome, one action and a large return of the product object. Keep the directory on the same field rather than adding a separate neutral footer.

## Page flow

**Storyline:** Promise → plain-language rationale → tangible product chapters → human proof → helpful resources → renewed invitation and product stage → directory.

### Broad platform introduction

1. **Promise** — Left-aligned purple opening with oversized tablet and company-logo strip.
2. **Rationale** — Full-width display paragraph, then numbered feature tabs with adjacent diagram.
3. **Capability chapters** — Repeated heading pairs, bright media diptychs and open indexed grids; technical chapter switches to black.
4. **Human proof** — Checkerboard quotes and alternating customer case-study splits.
5. **Assistance** — Blush resource and support chapter.
6. **Closing call** — Purple invitation, giant product object and integrated directory.

**Transfer:** Use broad chapters for distinct value families; keep the media devices and indexing rather than duplicating every section.

### Explain cost and remove buying uncertainty

1. **Promise** — Centered purple reassurance with one action and a short quote strip.
2. **Pricing** — Two full-height mint/pink fields, price mechanisms and feature rows.
3. **Model rationale** — Purple heading pair followed by horizontal pastel testimonials.
4. **Comparison** — Numbered ruled cost comparison.
5. **Advanced needs** — Black split with dark laptop and sales action.
6. **Objection handling** — Blush question list continuing into common resources.
7. **Closing call** — Shared purple product stage and directory.

**Transfer:** Explain the charging mechanism first, then alternatives, special needs and real questions.

### Make a complicated capability feel handled

1. **Promise** — Purple left-aligned opening with product tablet and trust marks.
2. **Problem framing** — Large editorial statement and indexed benefit grid.

4. **Human proof** — Checkerboard quotations.

1. **Introduction** — Compact centered purple title and support.
2. **Rationale** — Large display statement and staggered small white value cards beside a dark product object on gray.

## Writing

Warm, capable and lightly cheeky. Complexity is acknowledged without sounding bureaucratic; promises are framed as work the reader no longer has to do.

**Do not copy:** Do not reuse Lemon Squeezy or Wedges names, logos, cover art, proprietary UI, customer identities, quotations, prices, metrics, geographic coverage or business claims. Examples illustrate voice only; all new facts must belong to the new product.

- **Addressing the reader:** Address the reader as you and your business. The product team speaks as we, often taking responsibility with phrases such as we handle and we've got your back.
- **Rhythm:** Headlines are conversational sentence fragments or direct promises, often 5–12 words and sometimes longer in centered openings. Paragraphs use two to four short-to-medium sentences, with one medium-weight phrase carrying the benefit. Occasional puns and em dashes soften technical subject matter.

| Role | Pattern | Typical length | Examples of the pattern |
| --- | --- | --- | --- |
| Opening headline | State the job and audience, then reduce perceived effort. | 7–12 words | “Payments, tax & subscriptions for software companies”<br>“Payments & billing for SaaS companies made easy” |
| Support line | Name what becomes easier, or remove commitment anxiety with a three-part reassurance. | 15–35 words | “Selling digital downloads, subscriptions, and software licenses has never been easier, faster, or more secure.”<br>“Simple pricing with no hidden fees. It’s free to start — no trial, no contract, no risk.” |
| Chapter heading | Pair a concrete reader benefit with approachable colloquial language. | 5–12 words | “How much moola will you save with [Brand]?”<br>“Documentation so good you’ll cry” |
| Helpful heading | Speak like a helpful person, using a question or reassurance. | 2–13 words | “Need help?”<br>“There are no stupid questions — ask away, we’re all ears” |
| Action | Short verb-led label naming the immediate next step. | 1–5 words | “Get started”<br>“Read the case study”<br>“Download Figma File” |

**Words and phrasing to use:** easy; made easy; we handle; your business; we’ve got your back; all-in-one; no-code; joy to use; super-simple

**Avoid:** revolutionary ecosystem; synergize; unparalleled excellence; enterprise-grade transformation; fear-heavy compliance language

**Rules:**

- Lead with the reader's work or desired outcome, then explain the mechanism.
- Use technical nouns when they make a capability concrete; surround them with plain verbs.
- Keep humor to an occasional headline or aside, not every sentence.
- Highlight a meaningful phrase within a paragraph rather than setting the whole paragraph in medium weight.
- Write specific actions instead of repeating Learn more everywhere.

## Do's and Don'ts

### Do

- Keep 80px opening headlines at weight 400 and -0.04em tracking.
- Use 160px vertical space for major heading pairs, not compact dashboard spacing.
- Maintain the 1152px shared alignment and 40px side gutters at desktop.
- Let bright media planes reach the viewport edge in equal halves.
- Use 24px gaps inside open Feature tiles with 40px padding.
- Pair muted 18px/1.7 paragraphs with short weight-500 ink phrases.
- Return to the purple product stage before the four-column footer directory.
- Keep arrows about 12px so labels remain the focus.

### Don't

- Do not substitute heavy 700-weight display typography for the regular geometric headings.
- Do not turn square media planes into 24px-radius bento cards.
- Do not distribute every accent color across every paragraph; keep one color family per chapter.
- Do not place generic drop shadows under reading cards; depth belongs mainly to product imagery.
- Do not replace slash-number labels with oversized decorative feature icons.
- Do not shrink all supporting copy to 14px; reserve that scale for labels and metadata.
- Do not make black the default theme; it is a specialist-chapter contrast.
- Do not separate the footer with a white band after the purple closing product stage.

## Motion and responsive

### Motion

**Observed:**

- Primary action faces declare 0.28s cubic-bezier(0.215, 0.61, 0.355, 1) transitions; primary action backgrounds declare 0.1s.
- Feature tiles declare background-color 0.24s; resource text links declare color 0.16s linear; footer links declare color 0.2s.
- A proof/logo loop declares 40s linear infinite animation.

**Transfer:**

- Retain the distinction between layered pill-face movement and simple text-link color changes.
- Keep any horizontal proof loop slow enough to read rather than using a fast news ticker.

**Unknown:**

- Full entrance-animation choreography, exact scroll triggers and focus-visible styling are unspecified.

### Responsive

**Observed:**

- Declared width breakpoints include 390px, 479px, 480px, 767px, 768px, 990px, 991px and 1280px; pricing also includes 992px.

**Transfer:**

- Recommended adaptation: stack the hero copy before its large device, preserving the device's intentional edge overflow without horizontal page scrolling.
- Recommended adaptation: collapse flush splits and feature grids into one column; keep saturated media and pale copy as separate full-width planes.
- Recommended adaptation: collapse footer groups while preserving the continuous purple frame and clear title/link hierarchy.

**Unknown:**

- Exact narrow-screen type sizes, spacing and navigation behavior are unspecified; desktop type values are not asserted to be fluid.

## How to use this guide

1. Start from the Essentials and the first-screen recipe; where the guide offers variants, use the default named for a new marketing page.
2. Plan the page before building: map your content onto the section recipes and page flow, then check the plan against the Do's and Don'ts.
3. Build with the tokens and component specs; recreate signature graphics with their build recipes instead of generic decoration, and use the named font substitutes if a font is unavailable.
4. Render the page at desktop and mobile widths, compare it with the Essentials and the Don'ts, and fix the differences before you finish.
